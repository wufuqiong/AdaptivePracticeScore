# 评分算法说明（v1.1）

## 1. 目标与边界

为低龄儿童设计一个**进步可见、错误可恢复、后期不磨人**的熟练度积分系统：前期加分快，逐渐提高题目难度，高分挑战区要求独立答对，但每次成功仍有明显进展。

本实现是独立设计；借鉴 IXL SmartScore 公开的学习理念，**不声称知道或复现其未公开的计算公式**。分数不是百分比正确率，也不是正式测评。

## 2. 状态与接口

每个技能单独维护一个 AdaptivePracticeScore 值类型。属性：

| 字段 | 说明 |
| --- | --- |
| score | 当前熟练度（0–100） |
| answeredCount | 累计提交答题数，100 分后停止增加 |
| correctCount | 累计正确数；难度过低的答对题也计数 |
| unassistedCorrectStreak | 连续未提示、且题目难度达标的正确作答数量 |
| challengeCorrectStreak | 进入 90 分以后，连续独立正确 L5 题的数量 |
| recoveryBonusAvailable | 在挑战区答错以后，恢复加速奖励尚未消费 |

接口：

- **nextDifficulty**：下一题的最低要求难度 L1–L5；引擎不负责选题。
- **stage**：learning（0–69）、consolidation（70–89）、challenge（90–99）、mastered（100）。
- **isMastered**：是否达到 100 分。
- **submit(correct:questionDifficulty:usedHint:)**：输入结果、题目难度和提示使用状态，更新分数。
- **Update**：包含 previousScore、newScore、delta、nextDifficulty、milestoneReached、isMastered、wasEligibleForPoints。

wasEligibleForPoints 表示题目难度满足最低要求，不保证这次一定加分；如答错、使用提示或达到上限仍可能不加分。milestoneReached 只有一次提交向上跨过 70 / 80 / 90 / 100 才不为 nil。

## 3. 分数区间

| 作答前分数 | 无提示、难度达标且答对的基本奖励 | 答错扣分 | 最低难度 | 正确得分上限 |
| --- | ---: | ---: | --- | ---: |
| 0–19 | +10 | -2 | L1 | 70 |
| 20–39 | +8 | -2 | L2 | 70 |
| 40–59 | +6 | -3 | L3 | 70 |
| 60–69 | +4 | -3 | L3 | 70 |
| 70–79 | +3 | -4 | L4 | 80 |
| 80–89 | +2 | -4 | L4 | 90 |
| 90–99 | **+2～3** | **-4** | L5 | 100 |

每次依据**提交前的分数**选择区间。历史答错数量不影响后续加分，不使用隐藏的累计倍率。

普通区（0–89）：

~~~text
难度达标、独立答对：
  newScore = min(当前区间上限, oldScore + 基本奖励)

难度达标、使用实质性提示后答对：
  newScore = min(89, 当前区间上限,
                 oldScore + max(1, floor(基本奖励 / 2)))

难度低于要求而答对：
  newScore = oldScore

答错（任何难度）：
  newScore = max(0, oldScore - 当前区间扣分)
~~~

具体结果：79 分答对到 80 分，而不是 82；88 分用提示答对最多到 89，不允许借提示进入挑战区。

## 4. 90–100 挑战区

只有**未使用实质性提示、且题目难度至少为 L5**的正确作答才能加分。

- 挑战区连续正确第 1、2 题：通常 **+2**。
- 连续正确第 3 题及以后：通常 **+3**。
- 若此前在分数 90+ 时答错，恢复到 90+ 以后，在连续正确第 2 道挑战题触发一次 **+3** 恢复加速，并消费恢复标记。
- 错题扣 **4 分**，并清零挑战区连对计数；下一题按新分数自动选择最低难度。
- 挑战区题目难度不够、或用了实质性提示：不加分，并清零挑战连对计数。

为避免正常加分路径出现 99 分：如果当前低于 99，且当前计划的 +2 或 +3 会恰好得到 99，则把这一次加分切换为另一个值。仍然对总分封顶 100。**唯一 +1 的特殊情况是已经存成 99 分的旧记录**。

**路径 A：全对**

~~~text
90 → 92 (+2) → 94 (+2) → 97 (+3) → 100 (+3)
~~~

**路径 B：90 分答错，降级巩固**

~~~text
90 → 86 (-4) → 88 (+2/L4) → 90 (+2/L4)
   → 92 (+2/L5) → 95 (+3/L5,恢复奖励)
   → 98 (+3/L5) → 100 (+2/L5)
~~~

**路径 C：96 分答错**

~~~text
96 → 92 (-4) → 94 (+2) → 97 (+3) → 100 (+3)
~~~

孩子即使前面累计错过 15 道题，后来回到 90 分以后，仍可依靠正常的 +2、+2、+3、+3 达到 100 分；不会因历史错题被迫每次只加 1 分。

## 5. 难度映射与出题职责

~~~text
0–19   → L1
20–39  → L2
40–69  → L3
70–89  → L4
90–100 → L5
~~~

nextDifficulty 是**最低达标等级**，不是严格匹配等级；更高难度题同样可以获得积分。由于答错后分数下降，出题等级会自动下降。例如 90 分答错降为 86 分，下一题回到 L4，正确恢复到 90 才再次做 L5。

引擎只算分。宿主 App 负责题库等级、题目随机化、知识点覆盖、近期题目不重复、错误知识点复习等。请勿用重复出现的相同答案图来替代真正的 L5 测验。

## 6. 提示定义

usedHint=true 表示孩子得到实质性线索，例如揭示位置、排除错误选项、提示正确音节、展示部分答案。普通区答对只得一部分分数，挑战区不给分。

**重播音频、再次朗读题干、辅助阅读等通常不算提示**，不应仅因孩子重听而惩罚积分。由宿主 App 根据题型定义 usedHint 的语义。

## 7. 存档与边界

- 通过 Codable 保存所有必要状态，恢复挑战区连对次数和恢复奖励。
- 兼容缺少 challengeCorrectStreak、recoveryBonusAvailable 字段的旧版 JSON，分别使用 0 和 false 作为默认值。
- 从旧数据恢复时钳制 score 在 0–100，修正负答题数和大于答题数的正确数。
- questionDifficulty 必须是 1...5，传入无效难度会触发 precondition；请提前验证题库。
- 达到 100 后提交不再改变数据。要重新考核请创建一份新状态，并由宿主 App 自行保留旧记录。
- 99 分的旧存档只能用最后一次 +1 完成，这是数学上不可避免的边界情况。

## 8. 后续可调参数（当前未实现）

可以在未来 A/B 测试时抽离年龄档、扣分力度、80/90 结束门槛、知识点复习权重等。**当前代码的计分表固定**，便于跨 App 使用、复现与自动化测试。
